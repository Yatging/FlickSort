# FlickSort V3 verification record

Date: 2026-10-23 (Asia/Hong_Kong)

Build: `3.0.0`  
Asset set: `city-vehicles-v1`

## Completed checks

- Loaded the standalone page over local HTTP in a real Chromium browser.
- Completed Classic Demo Mode and confirmed a perfect run reports 4/4 classification, 2/2 navigation and Overall Score 100.
- Completed FlickSort Demo Mode using real pointer drags for all four diagonal directions. Also generated and verified one short-trajectory cancel, one user-labelled accidental-input Undo, and one classification during navigation.
- Downloaded and inspected Trials CSV and Events CSV. The log kept `content_judgment_error`, `gesture_cancel`, `navigation_mistouch`, and explicit `accidental_input` Undo data separate.
- Completed Full Pilot Mode from tutorial through 24 scored classification trials and four navigation trials. A deliberately wrong final classification produced 23/24 (96%) accuracy and Overall Score 97 with the fixed demonstration benchmark.
- Tested the results page at a 390×844 mobile browser viewport. The result card was approximately 496 px high and the document did not exceed the 844 px viewport.
- Loaded all 24 SVG stimulus URLs over HTTP with zero missing assets.
- Visually reviewed all 24 browser-rendered illustrations against their manifest bus/car flags and answer labels. Each target vehicle was distinct and the backgrounds contained no unplanned buses or passenger cars.
- Ran automated boundary checks for Overall Score, rounding, clipping and all six gesture mappings (next, previous, Edit, Keep, Maybe, Reject), plus short-motion cancellation.

## Honest remaining limitations

- `T_ref = 180 seconds` is a fixed provisional demonstration benchmark. It has not been validated by a pilot and must be frozen from pilot evidence before formal data collection.
- Independent human stimulus review is not complete. The manifest therefore remains `human_reviewed: false`, and `asset-review.html` is provided to conduct and document that review.
- Responsive behavior was verified in a real browser at a phone-sized viewport, not on physical iOS/Android hardware. At least one iPhone-class and one Android-class device should still be tested for pointer behavior, safe-area layout, CSV download and screenshot capture.
- Formal GitHub Pages availability must be checked after the deployment generated by the pushed commit finishes.
- Demo scores use 4 classification tasks and 2 navigation tasks, so they are labelled as previews and are not comparable with Full Pilot scores.
